# 小红书封面 AI 双封面对比测试 · 发布准备版

当前已迁入项目代码，并完成逐张参考原稿生成的 100 张模拟封面：沿用已确认的 5 张样图，新增 95 张。见 [完整样图库与统一预览](previews/generated-reference-library/README.md)。完整图库待用户审阅，尚未进入测试竞争池；页面可启动，封面测试会提示图库尚未接入。

进度与迁移范围见：[发布版迁移状态](docs/migration-status.md)。

后续开发和真实数据校准请先阅读：[开发指引与验证方案](docs/development-guidance-and-validation-plan.md)。

项目准备开源和收集真实 PK 贡献数据时，请同时阅读：[开源与真实数据贡献方案](docs/open-source-and-data-contribution-plan.md)。

这是一个只在本机运行的小红书封面相对选择测试工具。上传 2 张候选封面和笔记标题后，系统按测试模式抽取参考封面，让两个版本在相同测试条件下分别接受 100 个不同 AI Agent 的判断。当前提供四宫格和双列纵向信息流两种实验模式。模拟测试默认使用本机 Ollama 的 `qwen3.5:4b`，无需 API Key 或付费 API；真实校准记录仍可按模型分别统计。

需要 Node.js 22.13+（建议使用 Node.js 24 LTS），以支持内置 SQLite。

## 启动

### 每次启动（Windows PowerShell）

在已经完成首次安装和配置后，以后每次启动只需要：

```powershell
npm run dev
```

然后打开 `http://localhost:3000`。已有的 `.env.local` 会被自动读取，不需要在网页中再次填写 API Key。

### 首次运行

先下载本仓库并进入目录：

```powershell
git clone https://github.com/linsank2005/xiaohongshu-cover-simulator-public.git
Set-Location xiaohongshu-cover-simulator-public
```

如果还没有安装依赖或创建 `.env.local`，在仓库根目录执行：

```powershell
npm install
if (-not (Test-Path '.env.local')) { Copy-Item '.env.example' '.env.local' }
ollama pull qwen3.5:4b
```

运行测试前保持 Ollama 服务开启。默认连接 `http://127.0.0.1:11434`，模型名和地址可在 `.env.local` 中通过 `OLLAMA_MODEL`、`OLLAMA_BASE_URL` 修改；地址只允许本机回环地址。网页仍保留智谱等云模型选项，选择云模型时才需要对应 API Key。

按 `Ctrl+C` 停止服务。
### 只做代码验证

如果只想检查代码是否正常，可以复制执行：

```powershell
npm test
npm run typecheck
npm run build
```

其中 `npm run build` 会检查本仓库的模拟图库状态并执行生产构建。空图库允许准备阶段构建，不会恢复旧图。

### 常用运行命令

在项目根目录 PowerShell 中执行：

## 测试口径

- 每次测试需要上传 2 张候选封面，并输入同一个笔记标题。
- 四宫格抽取 1 组 3 张参考封面；双列纵向信息流抽取 1 组 9 张参考封面，两个候选版本分别共用对应模式的参考封面。
- 每个版本固定运行 100 个不同的 Agent，每个 Agent 只调用一次最终判断。
- 测试场景可以选择四宫格对比或纵向信息流；两个版本使用同一种场景。
- 模型输出格式错误时，最多对同一个 Agent 重试一次。
- 四宫格模式可选择 A、B、C、D；双列纵向信息流可选择 A 到 J；两种模式都可以选择 NONE。
- NONE 表示当前场景中的全部封面都没有达到自然点击阈值，属于有效的自然跳过。
- 每个版本的模拟选择率分母固定为 100 个 Agent。
- 两个版本使用同一组 Agent、参考封面和可复现的位置计划。
- 结果会展示两个版本的选择率、差值、自然跳过率、有效判断数、模型名称和提示词版本。
- 完成结果和历史记录会显示从任务创建到完成的总耗时，便于比较不同并发配置的实际速度。
- 该选择率表示当前模拟信息流中的相对表现，不等同于真实发布后的 CTR。
- 测试进行中可以点击“取消测试”；系统会停止后续请求并中止本地等待，取消任务不会作为完整结果统计。
- 模型调用失败时测试会标记为失败，不使用随机结果、固定点击率或 Demo 数据补齐。

## 真实 PK 校准

真实 PK 结果不需要在测试当天填写。测试完成后，系统会把本次双封面测试保存在本机；即使关闭网页、重启电脑，之后重新启动项目仍能在首页找回。

首页通过两个标签页分开“开始测试”和“真实 PK 校准”，测试进行中会保留在测试标签，避免误切走取消按钮。

### 推荐流程

1. 测试当天上传 2 张封面并完成模拟测试，记下或不必手抄测试 ID。
2. 在小红书使用同一标题和同一组候选封面进行真实封面 PK。
3. 过几天拿到结果后，重新运行项目并打开首页。
4. 在“所有已完成的双封面测试”中按标题、日期和封面缩略图找到对应记录。
5. 点击“记录真实赢家”，只选择“A 胜”“B 胜”或“无法判断”。系统自动绑定测试 ID、读取模拟赢家、保存 PK 日期并刷新一致率。

你不需要填写表格，也不需要重新上传封面。列表会优先显示还没有录入真实结果的测试。对于重复或不再需要的记录，可以点击“删除记录”；确认后会同步删除本地上传封面、结果快照、trial 明细和关联校准记录，删除后无法恢复。

### 批量导入（高级入口）

如果一次需要录入很多历史结果，仍可以在“真实 PK 校准”区域导入 CSV 或 JSON：

1. 点击“下载模板”，按列填写记录。
2. simulationTestId 填本系统生成的测试 ID，realWinner 填小红书 PK 的真实赢家 A 或 B。
3. validationStatus 使用 valid、invalid、inconclusive 或 cancelled；validationType 使用 prospective 或 retrospective。
4. 导入后，系统会读取本地测试快照，自动复核模拟赢家、标题、模式和模型。找不到测试 ID 或测试未完成的记录会提示并被排除。
5. 只有 valid 记录进入赢家一致率；取消、无明确赢家和无效记录单独统计。

校准面板会显示有效样本数、正确数、赢家一致率、10/30/50/100 条样本阶段门槛，并按验证类型、测试模式和模型拆分结果。校准记录与测试、trial、API usage 统一保存在本机 data/simulator.db，不会提交到 Git。旧 data/validation-records.json 首次访问时一次性导入，同一 simulationTestId 只保留更新时间最新的一条；原 JSON 保留作为迁移备份。

## 参考封面

发布版已准备 100 张通过 imagegen 生成的模拟参考封面。每张使用一张对应原封面作为生成参考，保留主要版式及画面比例，并重新生成画面、改写文案；这些是模拟示例，并非真实发布的封面。原始图片及来源信息未迁入本仓库。当前清单 data/reference-covers.json 为空，完整样图库位于 previews/generated-reference-library，等待用户审阅后接入。接入后，四宫格每次按现有权重抽取 3 张不重复封面；双列纵向信息流抽取 9 张不重复封面。两个候选版本复用同一组对应参考封面。当前不做主题、风格或相似度匹配，匹配层属于后续优化范围。

## 测试场景

四宫格模式将 4 张封面合成为一张 2×2 图片。两个候选版本使用同一批 100 个位置计划，候选封面位置在 A、B、C、D 之间均衡分配。

纵向信息流模式将 1 张候选封面和 9 张参考封面加上标题，合成为两列五行的 10 卡片长图，模拟小红书双列信息流中的连续向下浏览。候选位置在 A-J 之间均衡分配，两个候选版本复用同一组参考封面、Agent 和位置计划。当前纵向模式仍是单张合成图中的相对选择实验，后续可以继续拆分停留和点击行为。

## 结果保存

测试完成后，结果会保存到 `data/results/<测试 ID>/`，包括：

- `result.json`，保存完整统计口径、模型和提示词版本。
- `result.txt`，保存便于阅读的摘要。
- `feed-preview.jpg`，保存模型实际看到的测试场景示例。
- `references`，保存本次抽取的 3 张或 9 张参考封面。

## 双版本结果

每次测试会分别保存候选封面 A 和 B、两个四宫格预览、各版本统计、选择率差值和随机种子。历史结果仍保留原有单封面字段，新的测试结果以 variants 字段保存双版本数据。

## 稳定性与 API 用量

- 默认只监听 `127.0.0.1`。API 校验本地主机与 Origin；写请求必须带 `x-simulator-client: local`，页面已自动设置。不要用反向代理将本服务暴露到公网。
- 默认模型为本机 Ollama `qwen3.5:4b`，调用原生 `/api/chat`，关闭思考模式并使用 JSON Schema 限定选择范围。上下文设为 8192、单并发、单请求限时 180 秒，并保持模型加载 10 分钟，适配 8GB 显存和较慢的首次冷启动。
- 同一时间只接受一个测试，提交使用幂等请求 ID；刷新/重复提交不会重复执行同一任务。
- 每版 100 个独立 Agent，一次正常双封面测试为 **200 次模型请求**。格式错误、位置越界或确认尚未发送的连接故障共享一次重试机会，因此本地请求尝试硬上限为 **400 次**。HTTP 错误、已发送后的断线/超时、输出预算耗尽不自动重试。
- 本机 Ollama 固定单并发、单次完整请求限时 180 秒；GLM-4.6V 纵向模式并发为 2、限时 90 秒；其他组合并发为 5、限时 60 秒。模型连接使用独立连接池，连接阶段限时 30 秒，不依赖 Node 原生 fetch 较短的默认连接超时。连接重试等待 750 毫秒，可被取消打断；不自动跟随 API 重定向。
- 一次请求只携带一份画像、一张合成图和一次判断指令，没有累积对话。保留 `detail: high`、图片尺寸、完整行为画像与思考设置；只移除画像审计字段和 JSON 缩进。复用图片渲染结果减少本地开销，不等于减少模型图片 token。
- 任一不可恢复失败后停止派发，取消/失败会中止在途请求的本地等待。已到达服务商的请求仍可能计费，取消不能保证服务商停止推理。
- 请求数表示本地发起尝试；在写入账本与网络发送之间崩溃，或请求在到达服务商前被中止时，不能据此断言服务商已计费。
- API usage 按每一次请求持久化，包含重试、失败、取消和中断；token 仅累加服务商实际返回的数据。确认未发送的连接失败单列为 notSentRequests，其余缺失用量单独计数，不作为零消耗。缓存 token、思考 token 是细分项，不重复加入 totalTokens。账本保存脱敏错误码、HTTP 状态、服务商业务码、耗时和请求字节数，详情 API 的 apiUsage.lastError 可用于定位故障；不保存密钥或原始错误响应。
- 页面和 `result.json` 可查看请求数、重试和已报告 token。历史旧任务显示为未跟踪，不补造数据。
- SQLite 使用 WAL 与事务。任务带执行租约和心跳；服务中断后不会自动重放付费请求，过期任务在下一次访问时终结，最长约 30 秒。取消中断的任务恢复为 cancelled。
- 修改默认模型、思考预算或图片清晰度会影响实验基线，应经过配对验证后再调整。未做真实模型 A/B 验证前，不声称 token 百分比或排序质量收益。

行为回归：`npm test`。完整生产 HTTP 回归（本机模拟模型，不产生真实 API 费用）：先 `npm run build`，再 `npm run test:integration`。
