# 小红书封面 AI 双封面对比测试 · v0.8.0

上传 2 张候选封面和同一个笔记标题，让两个版本在相同条件下各接受 100 个模拟用户的判断。支持四宫格、双列纵向信息流，以及本机 Ollama 和兼容的云模型。

**无需注册账号。设置和记录保存在本机，可主动导出文件分享。** 参考图库由 100 张经过确认的 imagegen 模拟封面组成，并非真实发布的封面。本仓库采用独立 Git 历史，没有迁入原始参考图片或原笔记来源。

## 快速开始（Windows）

1. 安装 [Node.js 24 LTS](https://nodejs.org/en/download)（最低 22.13），然后下载并解压项目。
2. 双击根目录的 **`start-windows.cmd`**。首次启动会联网安装依赖并构建页面，保留这个窗口，完成后自动打开浏览器。
3. 点击右上角 **“模型设置”**，选本地或云模型，保存设置。
4. 输入标题、上传 A/B 两张封面，点击 **“开始双封面对比”**。

默认打开 `http://127.0.0.1:3001`；端口被其他项目占用时自动选择 3002–3010，并显示实际地址。重复双击会复用当前服务。按启动窗口内的 `Ctrl+C` 停止本工具；Ollama 单独运行。

### 本机 Ollama

在设置窗口中按顺序操作：

1. 点 **“下载安装 Ollama”**，安装官方 Windows 应用。
2. 点 **“启动 Ollama”**、**“刷新已安装模型”**。
3. 选择已有的本地图片模型，或填写模型名并点 **“下载模型”**。默认是 `qwen3.5:4b`，也支持其他安装在本机的视觉模型；下载进度在窗口内显示，可停止后继续。
4. 点 **“检测图片连接”**，成功后 **“保存设置”**。

Ollama 地址默认 `http://127.0.0.1:11434`，只接受本机回环地址。纯文字模型和 Ollama 云模型会被提示为不可用于此本机入口。模型越大，对显存、内存和时间的要求越高，完整 A/B 测试仍执行 200 次判断。

安装和本地运行方式参考 [Ollama 官方快速开始](https://docs.ollama.com/quickstart)。若按钮启动失败，可打开 Ollama 应用，或在 PowerShell 执行 `ollama serve`，再刷新列表。

### 云模型 API

在设置窗口选择智谱或 DeepSeek，填写 **API 基础地址、模型名称、API Key**，检测图片连接并保存。模型必须能接收图片，并兼容对应服务的对话接口；名称本身不保证具备图片能力。

- Key 保存到这台电脑的本地数据库，页面只显示“已配置”，不会回显已有密钥；留空沿用已有 Key，清除需点击专门按钮并保存。
- 两个智谱入口共用 Key。高级设置可调整单次超时、输出 token 上限和 Ollama 上下文长度。
- 检测图片连接会发送 1 张小图，云服务可能按一次请求计费；保存设置不调用模型。
- 云测试会将候选封面发送到你选择的服务商。运行中的测试使用开始时的固定配置，完成或取消后才能保存新配置。

原 `.env.local` 仍可作为默认配置；**网页中保存的配置优先**。日常使用无需查找或编辑这个文件。

## 我的记录与文件分享

“我的记录”独立于真实 PK 校准。已完成、失败、取消和正在运行的测试都会保留，关闭页面或重启后仍可查看。

- 按标题、模型、备注搜索，按来源和状态筛选；查看本机测试、添加或编辑备注、删除已结束的记录。
- 勾选记录后点击 **“导出 JSON”**：包含模拟统计、模型参数、参考图编号、时间、备注和已填写的真实结果，不含候选图片。
- **“导出封面 ZIP”**：在上述记录之外，附带 A/B 候选图片；单次最大 64MB，过大时分批导出。
- 没有勾选时导出当前筛选范围，包括分页之后的记录。导出文件不含 API Key、配置地址、数据库或本机绝对路径。
- 收集者点击 **“导入记录文件”**，导入他人主动发来的 JSON/ZIP，在“导入的记录”中本地汇总。无需对方的测试 ID 预先存在于收集者数据库，重复导入会更新已有记录。
- 记录由随机来源 ID 和测试 ID 区分，不收集登录账号。标题、备注和自选图片仍可能包含个人信息，请自行决定要分享哪些内容。

**要分享时只发导出的 JSON 或 ZIP，不要发整个 `data` 目录、`simulator.db` 或 `.env.local`。** 本地数据库包含你自己的模型密钥。工具没有自动上传、登录系统或在线数据库。

文件格式、备份、分发及测试步骤见 [本地使用与分发说明](docs/local-use-and-distribution.md)。

## 测试口径

- A/B 共用同一组 100 个画像、参考图和可复现的位置计划，分别运行，合计正常 200 次模型请求。
- 四宫格：1 张候选 + 3 张参考，位置 A–D；纵向信息流：1 张候选 + 9 张参考，双列五行，位置 A–J。均可选 NONE，表示自然跳过。
- 各版本完整结果的分母固定为 100；失败和取消只保留已完成判断，不补造完整结果。
- 选择率是模拟信息流中的相对表现，**不等同于真实发布后的 CTR**。
- 模型返回无效选择，或确认尚未发送的连接故障，最多重试一次；总请求尝试硬上限 400。HTTP 错误、发送后的断线、超时和输出预算耗尽不自动重试。
- 同一时间接受一个测试；重复提交不会重复执行。可取消后续请求，在途云请求仍可能计费。
- 结果显示实际模型、A/B 统计、自然跳过、请求用量、进度和总耗时。token 仅累加模型实际报告的数值，缺失用量单独计数。
- 默认本机模型单并发；GLM-4.6V 纵向并发 2，其他云组合并发 5。各入口使用独立超时和输出预算，可在设置中调整。
- SQLite 使用 WAL、事务和执行租约；支持多连接同时初始化。服务中断后标记未完成任务，不自动重放模型请求。

### 真实 PK（可选）

日常保存和导出不需要真实 PK 结果。在“我的记录”底部展开可选工具，可录入本机已完成测试的 A 胜、B 胜或无法判断，继续使用原有 CSV/JSON 校准流程。外部文件导入只汇总记录，不自动参与本机预测或准确率判断。

后续研究见 [开发指引与验证方案](docs/development-guidance-and-validation-plan.md) 和 [开源与真实数据贡献方案](docs/open-source-and-data-contribution-plan.md)。其中在线贡献、积分等是早期规划，不属于此版实现。

## 模拟参考图库与许可

100 张参考图逐张参考原稿，经 imagegen 重新生成画面和文案，再由用户确认后接入。PNG 位于 `public/reference-covers`，清单位于 `data/reference-covers.json`。抽样权重是配置，不表示生成图的真实效果；暂未实现主题或相似度匹配。

## 开发与检查

完整源码可执行以下命令：

```powershell
npm install
npm run dev        # 开发页面默认 localhost:3000
npm test
npm run typecheck
npm run build
npm run start      # 先构建，默认 localhost:3000
npm run test:integration # 本机 mock 模型，不调用付费 API
npm run launch     # 使用和双击启动相同的生产入口
```

完整模拟结果保存在 `data/results/<测试 ID>/`，包含统计 JSON/TXT、A/B 场景预览和选中的参考图。上传图、本地数据库和导入封面均在 `data` 下，已被 Git 忽略。不要用反向代理将本机服务暴露到公网。

仓库维护者在提交并检查代码后，可执行 `npm run release:bundle`，生成 `dist/xiaohongshu-cover-simulator-0.8.0.zip` 及 SHA-256 校验文件。它只打包纳入 Git 且在允许范围内的源码、文档、模拟素材，不打包 Git 历史、个人数据、密钥、依赖或构建产物。公开仓库和 Release 的发布需另行操作。
