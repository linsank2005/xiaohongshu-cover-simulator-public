# 本地使用、记录交换与分发 · v0.8.0

## 给使用者的最短指引

安装 Node.js 24 LTS → 解压项目 → 双击 `start-windows.cmd` → 点右上角“模型设置” → 配置本机 Ollama 或云 API → 保存 → 上传 A/B 封面开始测试。

首次启动会安装依赖和构建页面，需联网。之后代码与依赖没更新时直接启动。端口默认 3001，被占用时自动向后选择，终端会显示实际网址。重复双击复用同一服务。启动窗口保持打开，按 `Ctrl+C` 停止工具。

Ollama 可在设置窗口中启动、列出已安装模型、下载权重并查看进度；安装应用本身通过官方链接完成。纯文字模型和云端 Ollama 模型不用于本机入口。检测连接是一次独立图片请求，不会生成模拟测试记录。

## 记录交换

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| JSON | A/B 统计、实际模型及参数、提示词版本、参考编号、时间、备注、可选真实结果 | 小文件，先汇总结构化记录 |
| ZIP | records.json + A/B PNG 候选图片 | 同时查看封面，单次不超过 64MB |

JSON 上限 16MB，单次最多 5000 条。没勾选时导出全部筛选结果；勾选后仅导出选中的记录。ZIP 图片按比例压到最长边 1600，不改变本机原图。缺失图片会在页面提示，统计结果仍可导出。

收集者导入这些文件即可看到记录，不需要对方先在收集者电脑上运行测试。不同来源的同名测试 ID 分开保存；相同来源、相同测试 ID 再次导入会更新。收集者新增的备注会保留，单独导入 JSON 也会保留此前 ZIP 的图片。导入本机已有的原始记录会跳过，避免复制出第二份历史。

文件不含 API Key、模型服务地址、本机路径、原始请求或数据库。来源 ID 是随机生成的本机标识，不是登录账号。标题、备注及图片是使用者自己提供的内容，分享前自行检查；工具不自动上传。外部记录只用于查看和汇总，后续模型改进由维护者另行处理。

## 本地保存与迁移

- 设置、备注、测试账本保存在 `data/simulator.db`。
- 上传图在 `data/uploads`，模拟结果在 `data/results`，从记录 ZIP 导入的封面在 `data/imported-covers`。
- 同一台电脑升级时，先关闭工具，更新源码并保留原 `data` 目录和自己使用的 `.env.local`；重新双击会安装匹配的依赖并重建页面。
- 自己备份完整数据时，停止服务后复制自己的 `data` 目录。**此备份含本机 API Key，只供自己恢复，不能作为反馈文件发送。** 给维护者的反馈请使用页面导出的 JSON/ZIP。

## 给维护者的分发步骤

1. 完成测试、构建和 Git 提交。
2. 执行 `npm run release:bundle`，得到完整源码 ZIP 和 SHA-256 文件。包内有启动入口、提示词、100 张正式模拟图、生成记录、测试、说明和许可。
3. 使用者解压后先安装 Node.js，再双击启动；模型权重和云 Key 由使用者自行配置。
4. 公开 GitHub 仓库或上传 Release，属于单独的发布操作；当前准备流程不会更改仓库可见性。

分发包只纳入经过 Git 管理且在允许范围内的文件。不含 `.git`、`.env.local`、数据库、个人上传内容、测试结果、`node_modules` 或 `.next`。代码许可是 MIT，模拟素材范围见仓库 `ASSETS.md`。真实封面原仓库不属于此包。

## 新版本人工检查

- 双击启动后能打开页面，重复双击能复用同一端口。
- 设置中修改模型名称、保存并重新打开，配置保留；已有 Key 显示为已配置，不能回读密钥。
- Ollama 列表能识别本地视觉模型；纯文字模型不能用于测试。检测连接成功后开始完整 A/B 测试。
- 测试中能看到有效判断进度及实际模型，完成后“我的记录”能找到；添加备注、刷新页面后仍保留。
- 选择一条记录导出 JSON/ZIP，将文件导入另一份本地安装，能看到统计和备注，ZIP 还可查看 A/B 图片。
- 不需要真实 PK 就能执行上述记录流程；真实 PK 工具位于记录页底部的可选入口。
