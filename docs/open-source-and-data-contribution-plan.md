# 小红书封面 AI 模拟测试系统｜开源与真实数据贡献方案

> 文档用途：明确项目开源后的产品形态、真实 PK 数据贡献机制、积分权益、隐私边界和上线顺序，作为后续开发、运营和数据治理的共同依据。
>
> 适用范围：本地运行的双封面模拟测试、真实小红书封面 PK 校准，以及后续可选的公共数据贡献平台。

## 一、核心结论

项目采用“本地开源核心 + 可选数据贡献平台”的形态：

- 本地核心免费、开源、可独立运行；
- 用户的 API Key 始终保存在用户本机，API 调用在用户本地完成；
- 用户不登录、不贡献数据，也可以完成基础测试；
- 用户贡献真实 PK 结果后，获得个人校准、群体基准和高级实验功能；
- 封面图片和标题不默认上传，必须单独取得明确授权；
- 项目只评价模拟赢家与真实 PK 赢家的一致性，不承诺绝对 CTR 预测。

用户贡献数据换取的核心价值不是一个抽象积分，而是：

> 贡献越多真实结果，系统越能形成适合这个用户和其内容方向的个人校准能力。

## 二、产品分层

### 1. 本地开源核心

用户下载项目后，可以直接在本机完成：

- 上传 2 张候选封面；
- 输入同一个笔记标题；
- 选择四宫格或双列纵向信息流；
- 使用本地 `.env.local` 中的 API Key 运行测试；
- 查看模拟赢家、选择率、差值和实验快照；
- 关闭网页后，之后继续录入真实 PK 结果。

本地核心不要求用户先登录，也不要求用户上传数据。API Key、模型请求内容和本地历史默认不上传到平台。

### 2. 可选数据贡献中心

用户在真实 PK 结果产生后，在“真实 PK 校准”页面完成以下流程：

```text
找到历史测试
    ↓
记录 A 胜、B 胜或无法判断
    ↓
查看本次准备上传的字段
    ↓
选择授权等级
    ↓
上传匿名贡献包
    ↓
获得贡献凭证和积分
```

网页关闭或项目重启不影响这个流程，因为测试快照已经保存在本机。

## 三、数据贡献等级

### Level 0：仅本地使用

不上传任何数据，适合不愿意参与数据收集的用户。

### Level 1：匿名结构化结果

只上传模拟与真实 PK 的对照结果，例如：

```json
{
  "simulationWinner": "A",
  "realWinner": "B",
  "mode": "paired-cover",
  "modelProvider": "zhipu",
  "modelVersion": "GLM-5.3-Flash",
  "promptVersion": "v1",
  "testDate": "2026-09-08",
  "validationDate": "2026-09-10",
  "validationStatus": "valid"
}
```

用于：

- 计算模拟赢家与真实 PK 赢家的一致率；
- 比较不同测试模式和模型版本；
- 训练或调整相对排序校准层；
- 分析错误类型和稳定性。

这一等级不上传 API Key、标题和封面图片。

### Level 2：结果加封面素材

在 Level 1 基础上，用户明确同意上传：

- 两张候选封面；
- 笔记标题；
- 测试模式和实验上下文；
- 真实 PK 赢家。

用于训练视觉特征、参考封面匹配和更细粒度的内容分析。

封面素材必须单独授权，不能因为用户提交了真实赢家，就默认获得图片训练权。

## 四、用户激励方案

### 1. 积分规则

建议初始规则如下：

| 行为 | 建议积分 |
| --- | ---: |
| 提交 1 条有效 A/B 真实 PK 结果 | 10 |
| 提交“无法判断” | 1-2 |
| 补充完整实验上下文 | 2 |
| 同意贡献封面素材且确认拥有使用权 | 10-20 |
| 提交可复现 Bug | 5-20 |
| 参与官方校准实验 | 额外奖励 |

积分只奖励有效贡献。一个测试 ID 只能获得一次真实结果贡献积分。

### 2. 权益阶梯

| 阶段 | 条件 | 解锁内容 |
| --- | ---: | --- |
| 贡献者 | 1 条有效结果 | 贡献记录、数据凭证、贡献者身份 |
| 初步校准 | 5 条有效结果 | 个人一致率、错误类型分析 |
| 个人校准 | 10 条有效结果 | 个性化排序校准 |
| 高级用户 | 20-30 条有效结果 | 高级报告、实验能力、参考图增强功能 |
| 核心贡献者 | 50 条以上 | 新功能内测、优先支持、社区身份 |

基础测试、取消测试、历史查看和真实结果录入不应被积分锁住。积分应当解锁增值能力，而不是阻止用户正常使用产品。

### 3. 最值得提供的交换价值

优先级建议如下：

1. 个人校准档案：识别用户自己的模拟偏差；
2. 个性化封面排序：根据用户历史真实结果调整判断；
3. 群体基准：和匿名整体样本比较；
4. 高级实验报告：置信度、错误类型和稳定性分析；
5. 新实验模式和新模型的优先体验。

不要一开始承诺“上传一条数据就能提升模型准确率”。个人校准至少需要积累一定数量的有效样本，整体模型也应按样本阶段门槛逐步评估。

## 五、数据质量与反作弊

服务端需要具备以下约束：

- 一个测试 ID 只能提交一次结果；
- 服务端进行幂等校验，重复上传不重复发放积分；
- 只接受已完成且结构完整的测试；
- 真实赢家修改需要留下修改记录；
- 设置每日积分上限；
- “无法判断”允许提交，但积分低于明确赢家；
- 对异常重复、异常一致或异常高频账号进行抽样复核；
- 不得用积分机制逼迫用户在不确定时伪造 A 或 B；
- 每条数据记录数据版本、授权等级和贡献时间。

目标是收集高质量真实标签，而不是单纯追求上传数量。

## 六、数据治理和隐私边界

必须把代码授权和数据授权分开处理。

### 不上传的内容

- 用户 API Key；
- `.env.local`；
- 未经授权的模型凭证；
- 与测试无关的本地文件；
- 包含敏感信息的完整日志。

### 必须向用户说明的内容

- 上传了哪些字段；
- 字段用于校准、统计还是模型训练；
- 是否进入公开数据集；
- 是否允许商业使用；
- 是否可以申请删除；
- 已经用于模型训练的数据删除后如何处理。

项目应新增并维护以下文件：

- `LICENSE`：代码许可证；
- `PRIVACY.md`：隐私说明；
- `DATA-CONTRIBUTION.md`：数据贡献协议；
- `SECURITY.md`：安全问题报告方式；
- `CONTRIBUTING.md`：代码和数据贡献规范。

代码可以使用 Apache-2.0，数据则使用单独的数据贡献协议。封面图片和标题可能涉及用户原创权或第三方权利，不能直接套用代码许可证。

## 七、开源和上线方式

### 阶段一：开源准备

完成以下内容后再公开推广：

- 清理仓库中的密钥、私密数据和本地结果；
- 提供 `.env.example`；
- 完善安装、启动和故障排查文档；
- 增加数据贡献和隐私说明；
- 提供示例封面和示例结果；
- 增加敏感信息扫描和日志脱敏；
- 标明项目当前只做相对排序，不是 CTR 预测器。

### 阶段二：小规模内测

先邀请 20-50 名真实创作者使用，重点观察：

- 首次安装成功率；
- 完成真实 PK 的比例；
- 真实结果回填比例；
- 数据贡献授权比例；
- 积分权益的使用情况；
- 模拟赢家与真实赢家的一致率。

建议先累计 30-100 条有效样本，再决定是否扩大公开推广和启动全局模型调整。

### 阶段三：公开发布

对外传播时重点突出：

> API Key 在本地运行，测试结果可以延迟录入；贡献真实 PK 结果，可以获得个人封面排序校准能力。

公开渠道可以包括 GitHub、小红书 AI 创作者圈、独立开发者社区和内容创作者社群。

## 八、建议的技术实现顺序

### P0：贡献协议和数据结构

1. 定义 `ContributionRecord` 数据结构；
2. 增加授权等级和数据用途字段；
3. 生成匿名贡献包；
4. 明确 API Key 永不进入贡献包；
5. 增加本地待上传队列和失败重试。

### P1：服务端接收和积分账本

1. 增加账号或匿名贡献凭证；
2. 增加结果上传接口；
3. 增加幂等校验；
4. 增加积分流水；
5. 增加贡献历史查询；
6. 增加删除和撤回申请入口。

### P2：个人校准能力

1. 个人一致率统计；
2. 错误类型分析；
3. 个人内容方向的偏差分析；
4. 达到样本门槛后启用个人排序校准；
5. 保留 GLM 基线结果，不与其他模型混合。

### P3：公共数据集和高级功能

1. 发布匿名结构化数据快照；
2. 按数据版本训练校准模型；
3. 增加参考封面匹配；
4. 增加高级实验报告；
5. 再评估是否开放封面视觉训练数据。

## 九、核心衡量指标

上线后不要只看注册数和积分发放量，优先关注：

- 安装到首次测试的转化率；
- 测试完成到真实 PK 的完成率；
- 真实 PK 完成到结果上传的比例；
- 有效样本率；
- 模拟赢家与真实赢家的一致率；
- 贡献用户的 7 日和 30 日留存；
- 每条有效样本的获取成本；
- 数据撤回和异常样本比例。

最终要验证的是：

> 用户是否愿意持续贡献真实结果，并且这些结果是否真的能提高系统的相对排序稳定性。
