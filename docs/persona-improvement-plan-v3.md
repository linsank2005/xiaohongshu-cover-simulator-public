# 小红书封面 AI 模拟点击测试

## 人物画像与测试机制改进方案 v3

状态：待确认

本版只更新方案，不修改代码。

## 一、本版确认的修改边界

本版吸收以下明确决定。

- 删除 Demo 模式。
- 删除固定点击率和流程演示数据。
- 每次测试使用 100 个不同的 AI Agent。
- 每个 Agent 在每次测试中只做一次最终判断。
- 100 个 Agent 都可以选择 A、B、C、D，也可以四张都不选并返回 NONE。
- 保留当前四张封面组成四宫格、同时比较 A、B、C、D 的测试场景。
- 暂不重做顺序信息流、逐张曝光和四宫格场景本身。
- 参考封面暂时保持现有全库加权随机抽取逻辑，不增加匹配层。

本方案对“每个 Agent 点击一次”的解释是，每个 Agent 必须完成一次模型判断。Agent 可以选择 A、B、C、D 中的一张，也可以判断四张都不点击并返回 NONE。这里的一次表示每个 Agent 只产生一条最终判断，不表示每个 Agent 都必须选中用户上传的封面。

因此，一次测试会得到 100 条 Agent 判断记录。若选择结果等于用户封面所在的位置，记为一次用户封面命中。若返回 NONE，记为一次自然跳过。若选择其他封面，记为一次其他封面命中。

## 二、当前方案的事实盘点

当前画像保存在 `data/agents.json`，由 `AgentProfile` 类型描述。每个 Agent 有年龄、性别、职业、人生阶段、兴趣、内容偏好、消费习惯、点击习惯、标题敏感度、视觉偏好、内容避讳、性格、浏览目的和触发点等字段。

当前共有 50 个 Agent，统计结果如下。

| 维度 | 当前情况 |
| --- | ---: |
| 女性 | 32 人，64% |
| 男性 | 18 人，36% |
| 18 至 24 岁 | 8 人，16% |
| 25 至 34 岁 | 32 人，64% |
| 35 至 44 岁 | 10 人，20% |
| 平均年龄 | 29.9 岁 |
| 每次参与次数 | 每人 1 次 |
| 人群权重 | 没有显式权重 |

职业几乎一人一个，整体偏向产品、运营、咨询、财务、管理、设计、教育和其他专业岗位。学生、都市蓝领、服务业、普通家庭用户和低决策涉入用户的比例偏低。

当前加载器只校验 Agent 数量必须为 50。模拟任务把所有 Agent 等权放入任务列表，每个 Agent 只生成一次选择。默认 Demo 逻辑会用固定规则生成约 38% 的用户封面命中和约 8% 的 `NONE`，画像字段不会参与这部分结果。

当前参考封面库有 100 张素材，按照权重从全库随机抽取 3 张，不做主题、内容目的、风格或相似度匹配。当前参考库的内容权重大致为生活方式 54.1%、工作与成长 31.9%、消费与科技 14.1%。参考封面权重属于素材抽样权重，不能直接当作小红书用户权重。

## 三、第一性原理判断

封面点击需要估计的是某个用户在某个内容场景下的点击概率。稳定的人口属性只能提供较弱的先验，真正决定点击的变量包括当前需求、主题匹配、第一眼可理解性、视觉吸引力、好奇心、信任感、广告感和理解成本。

当前画像主要描述“这个人是谁”，对“这个人此刻为什么刷、想解决什么、愿意花多少注意力”描述不足。`browsePurpose` 是固定文本，同一个 Agent 在不同测试中不会出现找答案、做比较、放松刷内容和寻找灵感之间的状态变化。

当前画像还混入了很多点击之后才会发生的消费信息，例如是否愿意为专业服务付费、是否愿意购买高质量内容。这些字段对封面首屏点击的解释力有限，应和首屏点击行为分开。

本次重构的核心原则如下。

1. 人口属性用于确定人群构成。
2. 当前场景用于确定这一次浏览的需求状态。
3. 行为参数用于决定用户如何看封面并做出选择。
4. 内容主题用于判断封面与用户需求是否匹配。
5. 模型选择结果必须来自真实模型调用，不能由固定概率兜底。
6. `NONE` 是自然跳过结果，不能和用户封面未命中混为一种行为。

## 四、与小红书真实用户的对照

小红书官方公开信息显示，平台约有 3 亿月活用户，90% 内容为用户 UGC，月均用户搜索渗透约 70%，平台内容已经覆盖职场、情感、汽车、旅游和户外等多个一级类目。官方也强调真实分享、生活场景、个人特色和专业能力。[央视网对小红书商业化负责人的报道](https://culture-travel.cctv.com/2024/05/15/ARTItXiFiqTAAKBgk134uktj240515.shtml)

第三方活跃用户研究给出的方向性基准是女性约 72%、男性约 28%，18 至 24 岁约 43%，25 至 34 岁约 36%，35 岁以上约 20%，一线和新一线城市合计约 66%。这类数据主要来自活跃用户或达人粉丝样本，适合用作初始配额，不应视为全体月活用户的精确人口普查。[千瓜活跃用户研究摘要](https://www.yydm.cn/doc-view-43319.html)

艾媒 2025 年调研显示，用户使用小红书的主要目的包括获取信息 55.10%、学习新知 42.35%、购物消费 41.78%、社交互动 39.09% 和记录生活 35.27%。这些使用目的具有重叠性，不能直接相加成为互斥的人群比例。[艾媒用户目的数据](https://www.iimedia.cn/c1094/110928.html)

当前画像的主要偏差如下。

| 维度 | 当前画像 | 改进判断 |
| --- | --- | --- |
| 性别 | 女性 64%，男性 36% | 女性略低估，男性略高估 |
| 年龄 | 18 至 24 岁仅 16%，25 至 34 岁占 64% | 年轻用户明显不足，职场中段过度集中 |
| 城市 | 没有城市字段 | 无法体现高线城市和地域差异 |
| 职业 | 专业岗位密度很高 | 需要补学生、蓝领、服务业、家庭用户和创作者 |
| 使用目的 | 工作、效率、学习、商业判断偏多 | 需要补购物比较、生活决策、社交互动、兴趣表达和放松浏览 |
| 内容兴趣 | AI、商业、阅读、旅行较突出 | 美食、家居、宠物等生活内容兴趣明显不足 |
| 信任机制 | 证据、专业度、案例较多 | 需要增加普通人经验、生活场景、真实使用和社区口碑 |

## 五、100 个 Agent 的第一版配额

以下配额用于“大盘模式”的第一版。它是根据公开活跃用户资料形成的实验先验，后续应使用项目真实测试数据和历史封面表现校准。

| 年龄段 | 女性 | 男性 | 合计 |
| --- | ---: | ---: | ---: |
| 18 至 24 岁 | 28 | 15 | 43 |
| 25 至 34 岁 | 29 | 8 | 37 |
| 35 岁以上 | 15 | 5 | 20 |
| 合计 | 72 | 28 | 100 |

职业建议改成职业簇，不再追求 100 个不同职业。

- 学生、应届生和初入职场用户
- 都市白领和专业人员
- 都市蓝领、服务业和零售业
- 家庭管理、育儿和生活决策用户
- 内容创作者、电商经营者和自由职业者
- 管理者、成熟专业人士和高决策涉入用户

城市字段建议至少区分一线、新一线、二线、三线及其他。大盘模式可以把一线和新一线作为约 66% 的初始先验，目标人群模式应允许用户覆盖这一默认值。

## 六、画像字段的改进结构

每个 Agent 建议由四组字段组成。

### 人口属性

```json
{
  "ageBand": "18-24",
  "gender": "女",
  "cityTier": "新一线",
  "occupationCluster": "学生与初入职场",
  "familyStage": "单身或未育"
}
```

### 当前浏览状态

```json
{
  "entryMode": "推荐流",
  "contentMission": "找答案",
  "needIntensity": 0.8,
  "timeBudget": "短",
  "purchaseReadiness": 0.2
}
```

建议把当前浏览状态作为每次测试任务的一部分生成。同一个 Agent 可以保持人口属性稳定，但每次测试使用不同的当前状态。

### 封面行为参数

```json
{
  "titleReliance": 0.75,
  "visualReliance": 0.65,
  "readabilitySensitivity": 0.85,
  "realLifeScenePreference": 0.7,
  "humanPresencePreference": 0.6,
  "resultNumberSensitivity": 0.55,
  "adSkepticism": 0.8,
  "noveltySeeking": 0.65
}
```

### 证据与版本

```json
{
  "weight": 0.12,
  "source": "2025 active-user benchmark",
  "asOf": "2026-08-30",
  "confidence": "medium"
}
```

自然语言描述仍可以保留，用于增强模型理解，但关键行为必须有可校准的数值字段。

## 七、四选一或跳过的点击机制

本版保留四宫格场景，只调整结果生成规则。

1. 每次测试加载 100 个唯一 Agent。
2. 每个 Agent 只创建一个测试任务。
3. 每个任务调用选定的真实视觉模型。
4. 模型可以返回 A、B、C、D 或 NONE。
5. 返回无效 JSON 时，只重试同一个 Agent。
6. 重试成功后只保存一个最终结果。
7. 两次重试仍失败时，整次测试标记失败，不使用模拟结果补齐。
8. 用户封面的位置继续随机化。
9. 用户封面命中次数除以 100，得到本次用户封面命中率。
10. NONE 数量除以 100，得到本次自然跳过率。
11. 其他封面命中次数用于判断 Agent 是否愿意点击内容，但不计入用户封面命中次数。

Demo 模式需要完全删除，包括固定命中率、固定 `NONE` 概率、Demo 文案和缺少 API Key 时的静默替代逻辑。没有可用 API Key 时，测试应给出明确失败原因。

## 八、参考封面抽样规则

现阶段保留原有参考封面抽样逻辑。参考封面继续从现有 100 张素材库中按权重随机抽取 3 张，不增加主题、内容目的、风格或相似度匹配层。

- 大盘模式继续使用生活方式、工作与成长、消费与科技的现有素材池。
- 目标人群模式暂时不改变参考封面抽样逻辑。
- 参考库权重只影响素材出现概率，不代表对应用户群体的比例。

后续优化阶段再考虑增加主题、内容目的、封面类型、标题长度和信息密度的匹配层。

## 九、样本量和结果表达

100 个 Agent 每人一次判断后，样本量比当前 50 次更好，但仍然适合方向判断，不适合给出过度精确的绝对点击率。

建议结果页至少展示以下内容。

- 用户封面命中次数
- 用户封面命中率
- NONE 次数
- 自然跳过率
- 其他封面命中次数
- 100 个 Agent 的分群命中率
- 年龄、性别、职业簇和当前浏览状态的差异
- 模型名称和版本
- 有效判断数与失败数
- 结果生成时间

同一个封面需要比较多个版本时，建议保持同一组 Agent、同一组参考封面和同一组位置随机规则，再对版本做配对比较。

本版已经允许跳过。跳过需要单独报告，不能简单当作用户封面未命中，否则会把“不想看任何内容”和“看了其他封面”混成一种行为。

## 十一、确认后的测试计划

代码修改完成后，需要增加或更新以下测试。

- Agent 数量必须为 100。
- Agent ID 必须唯一。
- 每次测试必须产生 100 个不同 Agent 的最终判断。
- 每个 Agent 在一次测试中只能有一个最终判断。
- 返回结果只能是 A、B、C、D 或 NONE。
- API 失败时不能使用固定概率或 Demo 结果补齐。
- 用户封面命中率的分母必须为 100 个有效 Agent。
- 自然跳过率的分母必须为 100 个有效 Agent。
- 结果页和数据库中的总试验数必须为 100。
- TypeScript 类型检查和生产构建必须通过。

每次代码改动完成后创建对应 Git commit，交付前运行全部测试和验证命令。

## 十二、建议的实施顺序

第一步，删除 Demo 模式和固定点击率逻辑。

第二步，把 Agent 数量扩展到 100，并按年龄和性别配额重建画像。

第三步，补充城市、职业簇、当前浏览状态和数值行为参数。

第四步，强制每个 Agent 调用真实模型并完成一次 A 至 D 或 NONE 的有效判断。

第五步，增加用户封面命中率、自然跳过率、其他封面命中数和分群结果展示。

第六步，补充测试并运行类型检查、构建和真实模型链路验证。

第七步，再根据后续真实测试结果校准人群权重和行为参数。

第八步，再评估是否需要增加参考封面主题、内容目的和风格匹配层。
