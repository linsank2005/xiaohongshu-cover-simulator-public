# 小红书封面 AI 模拟测试系统

## 项目介绍、技术框架与真实点击率模拟优化路线

> 文档状态：基于当前代码实现整理。
>
> 核心目标：让模拟结果越来越接近真实小红书笔记在目标曝光场景下的点击率，为创作者提供可验证、可解释、可校准的封面点击反馈。

## 一、项目概述

本项目是一个本地运行的小红书封面相对选择测试工具。用户上传 2 张候选封面并输入笔记标题，系统按模式抽取 3 张或 9 张参考封面，让两个候选版本在相同的双版本信息流场景中分别接受 100 个带有不同用户画像的视觉模型 Agent 判断。当前提供四宫格和双列纵向信息流两种模式。

当前系统的价值在于把封面测试从“一个人凭经验看图”变成了一个可重复的相对选择实验：

- 视觉模型实际看到的是包含封面和标题的合成信息流图片，而不是只看一张孤立封面。
- 两个候选版本共用同一批 100 个 Agent、同一组参考封面和同一份均衡位置计划，结果可以进行配对比较。
- 100 个 Agent 有固定的人口与行为画像，两个版本各自保存 100 条判断记录。
- Agent 可以返回 `NONE`，允许自然跳过，不强迫模型为了完成任务而选择一张。
- 真实模型调用失败时，测试会明确失败，不用固定点击率、随机结果或 Demo 数据补齐。
- 每个结果保存模型、提示词版本、测试封面、参考封面和部分测试预览，具备基本的审计能力。

当前输出应称为“模拟信息流选择率”或“候选版本相对选择表现”，还不能直接称为真实小红书 CTR。真实 CTR 是某个笔记在真实用户、真实曝光、真实推荐和真实平台交互下的点击概率；当前系统测到的是在特定测试场景中，某个候选版本被选择的比例。

## 二、当前已经实现的能力

### 2.1 用户流程

1. 用户输入标题并上传 2 张 JPG、PNG 或 WEBP 候选封面，单张图片不超过 10 MB。
2. 用户选择视觉模型提供商：GLM-5.3-Flash、DeepSeek 或 GLM-4.6V；真实校准基线默认固定使用 GLM-5.3-Flash。
3. 服务端检查对应 API Key、文件类型、文件大小和标题长度。
4. 从 `data/reference-covers.json` 对应的本地素材库中按权重抽取参考封面：四宫格为 3 张，双列纵向信息流为 9 张，均不重复。
5. 将每张候选封面分别与对应数量的参考封面加上标题，按所选模式合成为两组四宫格或双列五行纵向信息流图片。
6. 对两个版本复用同一批 Agent 和同一份均衡卡片位置计划，模型返回无效 JSON 时，对同一个 Agent 最多重试一次。
7. 分别统计两个版本的选择次数、选择率、参考封面选择、NONE 次数和有效判断数，并计算版本差值。
8. 测试完成后保存双版本数据库记录和结果文件，前端轮询展示版本排名与对比结果。

### 2.2 当前测试口径

| 项目 | 当前实现 |
| --- | --- |
| Agent 数量 | 两个候选版本各使用同一批 100 个 Agent，每个版本各判断 1 次 |
| Agent 数据 | `data/agents.json`，版本 `persona-v1`，来源标记为 `synthetic_xhs_quota_v1` |
| 人口配额 | 女性 72、男性 28；18–24 岁 43、25–34 岁 37、35 岁以上 20 |
| 城市层级 | 一线 27、新一线 28、二线 25、其他 20 |
| 职业簇 | 学生、职场、专业服务、经营创业、内容创作、家庭与生活 |
| 参考封面 | 100 张；20 个细分赛道，每个赛道 5 张；消费与科技 20、工作与成长 30、生活方式 50 |
| 参考抽样 | 四宫格全库加权、不重复抽取 3 张；双列纵向信息流抽取 9 张；当前不按主题、标题类型或风格做匹配 |
| 测试场景 | 四宫格为 1+3 张、2×2；双列纵向信息流为 1+9 张、2 列×5 行；位置计划在两个版本间复用 |
| 模型输出 | 四宫格为 `A`–`D`，双列纵向信息流为 `A`–`J`，均允许 `NONE`；只允许结构化 JSON |
| 校准基线 | 默认使用 GLM-5.3-Flash；DeepSeek 和 GLM-4.6V 作为独立可选模型，不混入同一校准结果 |
| 候选版本指标 | 每个版本选择次数 ÷ 100，结果四舍五入为模拟信息流选择率 |
| 版本比较 | 输出两个版本的选择率差值和自然跳过率差异 |
| 失败处理 | 缺少 API Key、网络失败或最终结果无效时整次测试失败，不填充虚假结果 |

这里有一个必须保留的口径边界：`NONE` 是“这次没有一张封面达到自然点击阈值”，不是“用户封面没有被点击”。因此，用户封面未被选择、选择了其他封面、当前场景中的全部封面都被跳过，必须在分析中分开。

### 3.4 数据库中保存的关键事实

tests 表保存测试标题、两个候选封面路径、参考封面 ID、随机种子、状态、总试验数、模型和提示词版本。trials 表按候选版本保存 Agent ID、版本键、候选封面位置、当前模式全部卡片的实际位置顺序、模型选择、模型版本、提示词版本和重试次数。

当前已经具备结果可追溯的基础，双版本测试已经保存候选封面、参考封面、随机种子和位置计划。曝光场景、Agent 权重、原始模型返回、设备条件和更细的行为中间变量仍待补充，这会限制后续校准和误差分析。

## 四、第一性原理：系统究竟要估计什么

真实小红书 CTR 的基本对象不是“封面好不好看”，而是：

> 在给定用户、给定当时浏览状态、给定推荐曝光场景和给定笔记内容的条件下，这个用户看到该笔记后点击的概率。

可以把目标写成：

```text
真实 CTR(i)
  = E[ P(click = 1 | user, session, exposure, note, cover_i) ]
```

其中：

- `user`：人口属性、兴趣、关注关系、历史行为和对内容类型的熟悉度。
- `session`：推荐流或搜索流、当下需求、时间预算、连续浏览疲劳、是否在比较商品等。
- `exposure`：上下邻近内容、卡片尺寸、位置、曝光来源、发布时间、平台推荐强度和同屏竞争。
- `note`：封面、标题、正文前几行、作者/账号信任、内容新鲜度、商业/广告属性。

当前系统只覆盖了其中一部分：`user` 主要由合成画像近似，`cover_i` 和标题被放入图片，`exposure` 被简化为四宫格或纵向信息流，`note` 没有正文、作者、账号关系和平台曝光历史。因此，当前结果可以用于同一测试条件下的方向判断，但不应被解释为“这篇笔记发布后的真实 CTR 百分比”。

## 五、当前方案最重要的真实性缺口

### 5.1 指标对象不同：相对选择率不等于曝光 CTR

当前 100 次判断中，用户封面被选择 35 次，就会得到 35%。这表示它在该组四卡片竞争中的选择份额，不表示它在 100 次真实曝光中一定有 35 次被点击。

如果四张卡片都被强行放在同一个四宫格里，用户封面的概率受另外三张参考封面的强弱影响很大。参考封面变强或变弱，用户封面的结果就会变化，即使用户封面完全没有变化。

### 5.2 曝光生成机制不真实

目前参考封面从全库加权随机抽取，不按用户画像、笔记主题、内容目的、标题结构、视觉风格或真实推荐关系匹配。这样做能形成竞争，但不能代表目标笔记在真实推荐流中会遇到什么内容。

真实平台还会受推荐系统、关注关系、搜索关键词、发布时间、热点、账号历史表现和用户连续浏览轨迹影响。当前没有模拟这些变量。

### 5.3 载体仍然是近似场景

四宫格适合做快速的相对比较，也能通过随机位置减少固定位置偏差。当前纵向信息流模式使用 1 张候选封面和 9 张参考封面，合成为两列五行长图，并由模型一次返回最终选择，因此还没有完整模拟真实平台中的连续曝光、部分可见和停留过程。

### 5.4 Agent 是合成静态画像，不是经过行为校准的用户样本

当前 100 个 Agent 的性别和年龄配额已有明确约束，画像字段也包含标题依赖、视觉依赖、可读性敏感度、广告怀疑、猎奇倾向等数值参数。但这些参数目前主要作为提示词中的自然语言上下文，并没有用真实点击日志估计。

人口属性只能提供先验，不能自动推出点击概率。同一个人早上通勤时找答案、晚上放松刷内容、看到熟悉博主和看到陌生广告时，点击阈值会明显不同。

### 5.5 模型投票不是概率模型

每个 Agent 当前只产生一次离散选择。100 个 Agent 的选择比例看起来像概率，但它混合了画像差异、模型判断差异、提示词解释差异和参考封面随机差异，并没有经过概率校准，也没有置信区间。

模型返回一个选择，不代表模型对该选择有 90% 的把握；一次调用也无法区分“稳定偏好”和“随机波动”。

### 5.6 真实笔记信息不完整

当前测试输入了用户封面和标题，参考封面也有对应标题，但没有包含正文开头、作者身份、账号历史、发布时间、话题标签、商业合作标识、图片数量、笔记类型和搜索/推荐来源。

这些信息会影响信任、相关性和点击动机。如果目标是预测真实笔记 CTR，必须明确当前产品究竟预测“封面+标题在冷启动推荐流的点击倾向”，还是预测“完整笔记在某个账号和流量条件下的点击率”。两者不是一个任务。

## 六、未来优化方向：按真实性收益排序

以下方向指的是让模拟更贴近真实点击场景，不是给封面本身提出美术或文案修改意见。

### P0：先把指标和校准闭环建立起来

这是最优先的工作，因为没有真实标签，任何“更像真实”的判断都无法验证。

1. **明确预测对象**：至少拆成“推荐流首屏点击倾向”“搜索结果点击倾向”“目标人群中的相对排序”三个可选任务，禁止一个百分比覆盖所有场景。
2. **收集真实标签**：允许用户导入本人笔记的匿名汇总数据，例如曝光数、点击/阅读数、发布时间、流量来源、标题、封面版本和账号阶段。只接收用户有权使用的数据，保留脱敏后的聚合指标。
3. **建立校准集**：把真实笔记按主题、账号阶段、流量来源和曝光量分层，形成训练集、验证集和时间外测试集；不要只用高曝光爆款。
4. **做概率校准**：先用当前模拟分数作为特征，再用真实 CTR 做 Platt scaling、isotonic regression 或分层 Beta-Binomial 校准，输出“预测 CTR 区间”和“校准后排序”。
5. **固定评估指标**：至少跟踪 MAE、RMSE、Spearman 排名相关、分桶校准误差和不同主题/人群的误差；同时记录模型对版本变更的稳定性。

第一阶段的成功标准不是“模拟值看起来合理”，而是：在留出的真实笔记上，模拟值能解释 CTR 的相对排序，且预测区间具有可接受的覆盖率。

### P1：继续完善可对照的真实信息流实验

四宫格应保留为“快速相对比较基线”，纵向信息流作为第二种实验模式。后续重点是把纵向模式从一张长图中的一次选择继续推进为连续浏览实验。

- 使用接近真实客户端的纵向卡片尺寸、图片裁切、标题行数、边距、字体和可见区域。
- 模拟用户连续浏览一串内容，而不是只在四张图中选最优者。
- 增加推荐流、搜索流、关注流等曝光来源；不同来源应使用不同的用户任务和点击阈值。
- 控制上下文内容：目标笔记前后放入经过匹配的邻近内容，记录其主题、视觉密度和相对强度。
- 增加位置和顺序的反事实实验：同一用户、同一组内容在不同位置重复曝光，估计位置偏差。
- 把“继续滑动”“停留但不点”“点击”拆成两阶段或三阶段行为，而不是一步直接四选一。

推荐的基础行为链路是：

```text
是否停留/注意到
        │ 否
        └── 继续滑动
        │ 是
        ▼
是否产生点击动机
        │ 否
        └── 停留后离开
        │ 是
        ▼
点击笔记
```

这样才能把“封面吸引了注意力但没有点击”和“完全没有被看到”区分开，也更接近真实平台的漏斗。

### P1：建立有标签的参考曝光池，而不是只存图片

当前参考库的 100 张封面适合作为演示和初始对照，但还不是可用于 CTR 校准的曝光池。下一步应把每条参考笔记扩展为一个带来源和表现标签的样本：

```json
{
  "noteId": "...",
  "coverPath": "...",
  "title": "...",
  "category": "生活方式",
  "track": "美食",
  "contentType": "攻略/测评/经验/观点",
  "exposureSource": "推荐流",
  "impressionsBucket": "10k-50k",
  "ctrBucket": "p50-p75",
  "publishedAt": "...",
  "dataAsOf": "2026-08-31",
  "source": "...",
  "license": "..."
}
```

抽样时应先根据目标笔记的主题、内容类型、标题长度、视觉复杂度和曝光来源做匹配，再在相似样本中随机抽取。匹配的目标是减少无关变量，不是故意挑选更弱的对手来抬高用户封面结果。

参考样本最好按真实曝光量或目标场景的曝光分布加权，并保留每次抽样的候选池和权重，便于复现。

### P1：把人口画像和“当前场景”分离

Agent 不应只有一个长期静态 JSON。建议拆成两层：

```text
稳定身份：年龄、性别、城市、职业、家庭阶段、长期兴趣
当前场景：入口、当前需求、需求强度、时间预算、浏览疲劳、消费准备度、上下文
```

同一个稳定身份可以在不同测试中进入不同场景，例如：

- 搜索“油皮夏季防晒”的明确任务状态；
- 午休期间的短时推荐流浏览；
- 睡前放松、没有具体目标的连续刷流；
- 比较价格和真实体验的购买决策状态。

用户群体也不应默认 100 人等权。应支持人口权重、场景权重和目标受众模式，并在结果中同时展示“样本原始结果”和“按目标人群重加权结果”。

### P2：让模型输出可分析的中间变量，但不让理由替代真实标签

当前只保存最终选项，难以诊断模型为什么做出错误判断。可以要求模型在内部结构化输出以下字段，再由程序只使用合法字段：

- 是否注意到目标卡片；
- 主题匹配度；
- 第一眼可理解性；
- 好奇心/需求触发；
- 信任感与广告感；
- 点击阈值是否被突破；
- 最终行为及其置信等级。

这些字段用于解释和误差诊断，不能直接把模型自评理由当作真实 CTR。最终校准仍必须依赖真实点击数据。

为估计模型噪声，可在开发阶段对同一 Agent、同一场景做多次独立判断，比较同一输入的选择稳定性；生产或用户-facing 测试再根据成本选择是否只保留一次判断。

### P2：把随机性、位置偏差和不确定性纳入实验设计

- 为每次测试生成并保存随机种子，使参考抽样、卡片位置和场景都可复现。
- 比较两个封面版本时，复用同一批 Agent、同一批参考内容和同一组场景，采用配对差值，而不是分别跑两批完全不同的样本。
- 四宫格模式对 A/B/C/D 做位置均衡，确保每个封面在每个位置出现的次数接近。
- 结果同时报告点估计、样本量、`NONE` 率、有效判断率和置信区间；100 个 Agent 不应被表达成过度精确的真实百分比。
- 对单次随机参考组合做敏感性分析：同一封面更换多组匹配对照后，观察结果区间和排名稳定性。

### P2：补齐审计和可复现能力

建议在 `tests` 和 `trials` 之外增加一次运行的实验快照，至少保存：

- 运行 ID、创建时间、随机种子和测试模式；
- Agent 画像快照、人口/场景权重和画像版本；
- 参考候选池、最终抽样结果和抽样权重；
- 图像合成尺寸、裁切规则、标题渲染规则和卡片位置；
- 模型提供商、模型名、提示词版本、温度/推理配置和请求耗时；
- 原始模型返回的脱敏版本、解析结果、重试原因和失败信息；
- 模拟值、校准值、置信区间和校准模型版本。

当前 `sql.js` 适合本地单机原型。随着并发和历史结果增加，应考虑一次性事务写入、任务队列、幂等状态机以及更适合多请求并发的数据库，避免每条 trial 都打开、导出和关闭数据库带来的性能与一致性风险。

### P3：把产品表达从“一个神奇百分比”改为“有条件的预测反馈”

最终用户看到的结果建议包含：

- 预测 CTR 区间，而不是只有一个整数百分比；
- 预测所对应的场景、目标人群和曝光来源；
- 模拟样本量、有效判断数、自然跳过率和参考池版本；
- 相对排序、版本差值和在不同人群中的方向；
- 历史校准误差和结果置信等级；
- 明确提示“该结果不能替代真实发布数据”。

当用户比较多个封面时，应优先显示“在相同场景和相同对照下，版本 B 相对版本 A 的差异及稳定性”，而不是把某一次运行的绝对数值当作承诺。

## 七、推荐实施顺序与验收标准

### P0：测试任务可取消（0.5.0 已实现）

当前版本已完成取消链路：前端可发起取消，服务端持久化 cancelling/cancelled 状态，停止新请求并中止活跃请求，同时保留部分 trial、取消原因、取消时间和请求数。后续重点是用真实运行验证取消后的请求数和状态收敛。

后续修复必须同时覆盖前端、任务状态和模型调用链路：

- 前端在测试进行中提供“取消测试”按钮，并明确显示取消中的状态。
- 服务端增加可持久化的取消状态，例如 `cancelling` 和 `cancelled`，避免仅依赖浏览器状态。
- 取消后不再调度新的 Agent 请求；正在进行的请求通过 `AbortController` 尽快中止。
- 已取消的任务不得继续写入 `completed`，也不得把部分结果当成完整测试结果展示。
- 保留已完成的 trial、取消时间、取消原因和已消耗请求数，便于审计 API 消耗和排查问题。
- 前端停止轮询或切换为取消结果，并允许用户重新发起一次全新测试。

验收标准：点击取消后，服务端不再产生新的模型请求；任务最终状态为 `cancelled`；历史记录能区分“正常完成”“失败”和“用户取消”；重新测试不会复用上一次任务的运行状态。

| 阶段 | 重点 | 主要交付物 | 验收标准 |
| --- | --- | --- | --- |
| 0. 基线固化 | 定义当前指标并保存现状 | 四宫格基线说明、运行快照字段设计 | 任意一次结果可复现，口径不再混用 |
| 1. 真实标签闭环 | 收集、脱敏和整理真实 CTR | 标准数据表、分层校准集、评估脚本 | 能在留出集上报告误差和校准曲线 |
| 2. 真实信息流场景 | 增加纵向卡片、连续浏览和行为漏斗 | 推荐流/搜索流场景、停留-点击两阶段判断 | 场景变量可配置，位置偏差可测量 |
| 3. 匹配参考池 | 用内容和曝光特征匹配对照 | 带表现标签的参考库、候选池快照 | 同一目标笔记重复测试的结果方差可解释 |
| 4. 人群与场景权重 | 稳定身份和当前状态分离 | 目标人群模式、重加权统计 | 结果可回答“对谁有效、在什么场景有效” |
| 5. 校准与不确定性 | 输出预测区间和稳定性 | 校准模型、置信区间、配对比较 | 模拟排序与真实排序达到预设相关性 |
| 6. 工程化 | 可取消、可复现、可并发、可审计 | 取消控制、任务队列、幂等、实验快照、历史版本 | 取消后无新请求、失败可恢复、结果可追溯、并发写入稳定 |

## 八、最值得立刻做的五件事

如果只安排下一轮迭代，建议按以下顺序：

1. 建立真实数据导入和评估脚本，先保证模拟赢家与小红书封面 PK 赢家可以持续对照。
2. 把页面和文档中的“真实点击率”改成“模拟信息流选择率”，直到完成真实标签校准。
3. 设计真实数据导入格式和评估脚本，先建立 50–100 条以上有曝光量的历史笔记样本。
4. 在保留四宫格基线的同时，继续完善纵向信息流实验模式，并把“停留”和“点击”拆开。
5. 为参考封面增加内容类型、曝光来源、发布时间和表现分桶，按目标笔记匹配参考池；同时保存随机种子、Agent/场景快照和每次 trial 的完整实验上下文。

## 九、结论

当前项目已经完成了一个重要的原型跃迁：它不再是固定规则或 Demo 点击率，而是一个真实视觉模型驱动的、带合成用户画像的相对选择实验。现阶段最大的限制不在模型数量，也不在封面视觉分析能力，而在“模拟场景”和“真实 CTR”之间缺少可验证的映射。

真正的优化主线应是：

```text
定义正确指标
  → 采集真实标签
  → 构造真实曝光场景
  → 匹配真实对照样本
  → 模拟停留与点击行为
  → 用真实数据校准
  → 用配对实验和不确定性输出反馈
```

只有完成这条闭环，系统给出的数字才有机会从“模型对封面相对偏好的投票”升级为“对真实小红书点击率有统计依据的预测反馈”。
