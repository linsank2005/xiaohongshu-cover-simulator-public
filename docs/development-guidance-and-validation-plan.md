# 小红书封面 AI 模拟测试系统｜后续开发指引

> 文档用途：记录已经确认的产品边界、真实验证口径和后续开发顺序，作为后续改代码、设计数据结构和判断功能是否应该加入的共同依据。
>
> 基线版本：0.7.0
>
> 当前核心结论：本项目首先是“发布前双封面相对排序工具”，不是绝对 CTR 预测器。

## 一、产品定位

系统要回答的问题是：

> 在相同标题、相同参考环境和相同模拟用户条件下，候选封面 A 和候选封面 B，哪一张更值得发布？

第一阶段只关注相对排序，不输出或承诺“这篇笔记发布后会有多少 CTR”。页面、结果文件、文档和对外描述都必须使用以下表述：

- 模拟信息流选择率；
- 候选版本相对选择表现；
- 模拟第一名；
- 模拟结果与真实 PK 赢家的一致率。

不得把模拟选择率直接写成真实 CTR，也不能因为使用了 100 个 Agent 就暗示结果等同于 100 个真实用户。

## 二、已确认的第一阶段范围

| 项目 | 第一阶段约定 |
| --- | --- |
| 目标用户 | 先服务自己的 AI、职场和效率类内容，不一开始覆盖所有小红书赛道 |
| 输入 | 2 张候选封面、同一个笔记标题、测试模式、模型 |
| 主要实验 | 双封面 A/B 配对比较 |
| Agent | 当前每个版本 100 个合成画像；后续采用分层测试，不盲目扩到 1000 个 |
| 默认模型 | GLM-5.3-Flash（智谱），作为真实校准基线 |
| 其他模型 | DeepSeek、GLM-4.6V 可以独立测试，但不混入 GLM 校准结果 |
| 四宫格 | 1 张候选封面 + 3 张参考封面，2×2 布局 |
| 双列纵向信息流 | 1 张候选封面 + 9 张参考封面，2 列×5 行布局 |
| 参考图 | 当前保持全库加权随机抽取；主题和风格匹配后置 |
| 结果 | 两个版本的选择率、NONE 率、位置计划、预览图和完整实验记录 |

当前纵向模式仍然是长图中的一次最终选择，不是真实的停留、滑动和点击行为。多阶段行为模拟、多候选 PK 和参考图匹配，必须在第一阶段验证稳定后再做。

## 三、真实验证闭环

真实标签来自小红书的封面 PK 功能，而不是绝对 CTR 数值。第一阶段的标准流程是：

```text
准备同标题的候选封面 A/B
        ↓
在本系统中完成模拟测试
        ↓
记录模拟第一名和 simulationTestId
        ↓
使用同一标题、同一组候选封面参加小红书封面 PK
        ↓
记录真实 PK 赢家
        ↓
判断模拟第一名与真实赢家是否一致
        ↓
累计有效样本，分析排序准确率和错误类型
```

第一阶段固定使用双封面 PK。即使小红书支持更多封面，也不要在模拟系统尚未支持多候选排序前，把 3 张或 4 张 PK 结果直接混入双封面准确率。

历史笔记和后续新笔记都可以使用：

- 有模拟记录后再参加 PK 的，标记为前瞻验证；
- 先完成发布、之后补跑模拟的，标记为回溯样本；
- 回溯样本可以用于探索，但不要和严格前瞻样本混为同一个准确率结论。

## 四、验证数据规范

真实结果通常在模拟测试完成数天后才会产生，因此第一入口必须是持久化的历史测试列表，而不是依赖当天网页状态。测试完成后，系统自动保留实验快照；用户之后重新启动项目，在“所有已完成的双封面测试”中按标题、日期和封面缩略图找到记录，只需点选 A 胜、B 胜或无法判断。系统自动绑定 simulationTestId、读取模拟赢家、记录 PK 日期并刷新统计。

CSV/JSON 保留为批量导入和迁移用的高级入口，不作为日常验证要求。建议字段如下：

```json
{
  "validationId": "val-0001",
  "simulationTestId": "test-id",
  "source": "xiaohongshu-cover-pk",
  "validationStatus": "valid",
  "validationType": "prospective",
  "title": "笔记标题",
  "coverA": "候选封面 A 的稳定标识",
  "coverB": "候选封面 B 的稳定标识",
  "simulatedWinner": "A",
  "realWinner": "B",
  "testMode": "vertical",
  "model": "GLM-5.3-Flash",
  "simulationDate": "2026-09-07",
  "realPkDate": "2026-09-08",
  "notes": "可选说明"
}
```

建议保留的状态：

- `valid`：标题、候选封面和 PK 结果均可对应，进入准确率分母；
- `invalid`：封面、标题或测试记录无法对应，不进入准确率分母；
- `inconclusive`：数据量过低、差距过小或真实结果不可信，单独统计；
- `cancelled`：模拟任务被用户取消，不进入准确率分母。

如果小红书可以提供曝光、阅读、点赞、收藏、评论等汇总数据，可以作为可选字段保存，用于解释异常样本，但第一阶段准确率仍以“模拟赢家是否等于真实 PK 赢家”为主。

## 五、准确率和迭代口径

第一阶段唯一的核心指标是赢家一致率：

```text
赢家一致率 = 模拟赢家与真实赢家一致的 valid 样本数 ÷ valid 样本总数
```

结果至少要显示：

- 正确数量 / 有效样本数；
- 赢家一致率；
- `inconclusive` 数量；
- `invalid` 数量；
- 前瞻样本与回溯样本分别的结果；
- 按测试模式和模型版本拆分的结果。

不能使用以下方式替代准确率：

- 把模拟选择率当成真实 CTR；
- 把所有无法判断的样本强行算错或算对；
- 只保留预测正确的案例；
- 混合 GLM、DeepSeek 和 GLM-4.6V 后计算一个总准确率。

### 样本阶段门槛

- 10 条有效样本：只做观察，不改模型；
- 30 条有效样本：允许第一次系统性复盘和单变量调整；
- 50 条有效样本：检查调整后的方向是否稳定；
- 100 条有效样本：形成第一版阶段性结论。

每次调整必须记录：调整原因、变更文件、提示词/模型版本、调整前后指标。一次只改变一个主要变量，避免无法判断是哪项改动产生影响。

### 错误分类

模拟与真实赢家不一致时，至少归入以下一类：

- 标题与封面理解偏差；
- 参考封面竞争环境不合理；
- Agent 画像与目标人群不匹配；
- 位置或信息流模式影响；
- 模型随机波动；
- 小红书 PK 数据不稳定；
- 两张封面本身差异过小。

## 六、后续开发优先级

### P0：测试任务可取消（0.5.0 已实现）

当前版本已完成该 P0 的代码闭环。后续重点是通过实际取消操作验证：取消后不再新增模型请求、历史状态稳定保持为取消状态，并能从历史记录中区分 completed、failed 和 cancelled。

这是当前最优先的稳定性问题。点击开始后，用户必须能够停止任务，避免持续消耗 API 配额。

实现必须覆盖完整链路：

1. 前端测试进行中显示“取消测试”按钮；
2. 服务端增加取消接口和持久化状态，例如 `cancelling`、`cancelled`；
3. 取消后不再调度新的 Agent 请求；
4. 正在执行的请求通过 `AbortController` 尽快终止；
5. 已取消任务不能继续写入 `completed`；
6. 部分 trial、取消时间、取消原因和已消耗请求数要保留；
7. 前端停止继续等待，显示取消结果，并允许新建测试；
8. 取消后重新测试必须创建新的任务 ID，不能复用旧任务状态。

需要明确：已经被远程模型服务接受的请求不一定能在服务端真正撤回，但本地系统必须停止继续发起请求，并尽快中止本地等待。

### P0：验证数据和实验快照（0.7.0 已实现）

当前版本提供历史测试列表、网页点选真实赢家、本地验证记录持久化、CSV / JSON 批量导入和 simulationTestId 复核。网页点选默认生成稳定的校准记录；导入记录会保留 valid、invalid、inconclusive、cancelled 四类状态，便于后续审计和修正。已完成双封面测试支持人工删除，删除时同步清理本地结果快照、上传封面、trial 明细和关联校准记录。

在开发复杂行为模拟前，先让每次实验都能被复核：

- 保存 `simulationTestId`；
- 保存候选封面、标题、测试模式、参考封面和随机种子；
- 保存模型、提示词版本和位置计划；
- 保存模拟第一名和完整版本结果；
- 支持导出和读取验证 CSV/JSON；
- 不能让历史数据依赖当前页面状态才能解释。

### P1：验证结果统计（0.6.0 已实现）

当前版本提供基础校准面板，展示赢家一致率、正确数 / 有效样本数、样本阶段门槛，并按前瞻/回溯、测试模式和模型拆分结果。只有 valid 样本进入准确率分母，取消或无明确赢家的记录不会被强行算作错误。

建立最小验证报表，并让日常录入足够简单，回答：

- 当前赢家一致率是多少；
- 样本量是多少；
- 前瞻样本和回溯样本分别如何；
- 哪类错误最多；
- GLM 基线是否比其他模型稳定；
- 重复测试是否能保持相同排序。

### P2：参考封面匹配

当前先保持全库加权随机抽样，作为基线。稳定后再给参考封面增加：

- 主题；
- 内容类型；
- 标题类型；
- 发布时间；
- 曝光或表现分桶；
- 来源和授权信息。

匹配抽样的目标是减少无关差异，不是挑选弱对手抬高候选封面结果。每次抽样都要保存候选池和最终结果。

### P3：行为真实性和多候选扩展

以下能力暂缓：

- 停留、继续滑动、点击的多阶段行为；
- 3 张或 4 张候选封面排序；
- 1000 个 Agent 的常规运行；
- 实时抓取小红书内容；
- 标题、选题等更多测试类型。

只有在双封面排序有真实验证数据后，才评估这些扩展是否真的能提升准确率。

## 七、测试规模策略

当前正式测试仍是每个版本 100 个 Agent。后续可以增加分层运行模式：

```text
快速筛选：每个版本 30 个 Agent
正式确认：每个版本 100 个 Agent
研究验证：每个版本 500–1000 个 Agent
```

扩大 Agent 数量前必须先确认：

- 错误是否主要来自样本量不足；
- 单个模型判断是否足够稳定；
- 参考环境是否合理；
- 真实赢家数据是否足够可靠。

如果主要问题来自参考图、标题或人群设定，增加 Agent 只会更稳定地放大错误。

## 八、开发和交付规则

- 真实校准固定使用 GLM-5.3-Flash；其他模型作为独立实验组。
- 修改测试流程时，同时更新数据库、API、前端、结果导出、测试、文档和版本记录。
- 每次改动都必须有对应 Git commit。
- 代码交付前至少运行 `npm test`、`npm run typecheck` 和 `npm run build`。
- 不得打印或提交 API Key；继续使用现有 `.env.local` 配置。
- 新功能必须明确属于“当前实现”“已确认待办”或“后续暂缓”，不能把规划内容写成已经完成。
- 任何影响模拟口径的改动都要更新 `promptVersion` 或实验版本说明。

## 九、阶段性完成标准

第一阶段不是“功能最多”，而是满足以下条件：

1. 双封面在同标题、同参考环境下可重复测试；
2. GLM-5.3-Flash 作为唯一校准基线；
3. 测试任务可以取消且不会继续产生新的请求；
4. 每次模拟都有可追溯的实验快照；
5. 测试关闭后仍能从历史列表找到实验，并只点选真实 PK 赢家；
6. CSV/JSON 可以作为批量导入备用入口；
7. 系统能报告模拟赢家与真实赢家的一致率；
8. 错误样本可以分类和复盘；
9. 在至少 30 条有效样本前，不根据个别错误随意改模型。

达到这些条件后，才进入参考池匹配、连续行为和多候选扩展阶段。
